## DPI 与灵敏度适配

基准来自 V5 的现有估算：800 DPI、灵敏度 0.3、显示器宽度 2560、增益 2.68。不是新做的游戏测量。

软件输出相对位移计数，不应再次按物理鼠标 DPI 缩放：

```
eDPI = DPI × 游戏基础灵敏度
输出增益 = 2.68 × (0.3 / 当前灵敏度) × (2560 / 所选显示器完整宽度)
输出上限 = clamp(round(基础档位上限 × 0.3 / 当前灵敏度), 10, 480)
```

- 自动建议可在“位移增益”中手动覆盖；输入增益即切换为手动，回车或应用后生效。手动值单独保存，换 DPI / 灵敏度或切档不会覆盖已应用的手动增益；“恢复自动”仍须回车 / 应用提交。
- **DPI 是手感/eDPI 信息，不是额外的输出计数倍率**。只把 DPI 从 800 改为 1600、灵敏度保持 0.3 时，软件计数增益不翻倍或减半。
- 1600 DPI / 0.15 与 800 DPI / 0.3 的 eDPI 相同，但相同屏幕偏差需要的注入计数不同；不能仅按 eDPI 比例转换。
- 使用的是完整显示器宽度，不是中心裁剪的 640 像素，也不是神经网络输入尺寸。
- 增益超出 V5 的 0.05–8 范围时拒绝应用；输出上限达到 10/480 边界会明确提示，不静默声称完全适配。
- 只估算**不开镜、所选显示器全屏、相同视场与投影条件**。窗口化、黑边或拉伸不纳入自动标定。开镜倍率、拉伸画面、不同输入链路或 Windows 指针加速可能需要额外标定。两个数字不能保证覆盖所有情形。
- 仅改变 V7 参数，不修改鼠标驱动、游戏配置、系统灵敏度或其他版本。

依据与推导：微软区分了原始鼠标数据和经过系统加速的光标消息；Riot 曾明确说明 VALORANT 使用 Raw Input。上述比例公式是结合 V5 的“像素偏差→相对计数”实现所作的工程推导，不是官方游戏标定公式。参见 [Microsoft 原始鼠标输入说明](https://learn.microsoft.com/en-us/windows/win32/dxtecharts/taking-advantage-of-high-dpi-mouse-movement)、[MOUSEINPUT 相对移动说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-mouseinput)、[Riot 3.07 输入说明](https://playvalorant.com/en-us/news/game-updates/valorant-patch-notes-3-07/)。
